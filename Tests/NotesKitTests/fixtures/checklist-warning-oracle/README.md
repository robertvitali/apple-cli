# checklist-warning oracle fixture (NOTES-M8)

Ground truth for `NotesText.detectChecklistAttempt`, generated by running the oracle's OWN
three regexes (transcribed verbatim from `apple-notes-mcp`'s `contentWarnings.ts`) over a
corpus, rather than by reasoning about what they should match.

- `gen-corpus.mjs` — the generator. Deterministic (LCG, seed `20260803`), so re-running it
  reproduces `corpus.json` byte-for-byte. Regenerate with `node gen-corpus.mjs > corpus.json`.
  Named rows come in three groups: the 14 word-boundary rows a hand-written port gets wrong,
  the hand-picked rows asserted inline in `ChecklistWarningTests` (so every verdict that test
  carries is re-derived by the checked-in corpus), and the ECMAScript-vs-ICU divergence probes
  (line-terminator set of `(?m)^`, the `\s` class, ASCII-only `\b`, `(?i)` full case folding).
  Randomized rows then assemble fragments aimed AT each rule's boundaries — including a
  non-ASCII/control alphabet, because that is where JS (no `u` flag) and ICU semantics part
  ways.
- `corpus.json` — 536 unique rows, 81 positive, 366 carrying non-ASCII or control characters.
  Counts are pinned in `ChecklistWarningTests.corpusAgreement` so a truncated or
  differently-regenerated fixture cannot masquerade as a pass.
- `mutate.py` — mutation harness for the detector AND the response-builder wiring (the two
  reviewer-named wiring mutants — emit `warning: nil`, feed the detector the title — are
  included). It rewrites the TRACKED `Sources/NotesKit/NotesText.swift` in place with no
  automatic restore: copy the file aside first and `cp` it back after each measurement, or a
  survived mutant could be committed silently. Anchors target the executable pattern-constant
  lines on purpose: the doc comment above the function quotes the oracle's JS regexes verbatim,
  so a bare-pattern search matches the COMMENT first and mutates nothing executable — two
  mutants "survived" that way before it was caught. It prints `APPLIED::<name>` or
  `ANCHOR-MISS::<name>` — never trust a run that did not print `APPLIED`.
- `redos.swift.txt` — timing probe for catastrophic backtracking. The `.txt` suffix keeps
  SwiftPM from compiling it into the test target (any bare `.swift` under `Tests/` is treated
  as a test source and top-level statements fail the build); run it with
  `swift redos.swift.txt`. The html regex it measures is labelled RETIRED: the shipped code
  replaced it with a linear scan (`NotesText.htmlCheckboxAttempt`) after review measured the
  `[^>]*` backtracking at 0.46/1.82/7.48/29.6 s for 6/12/24/48 KB of repeated unterminated
  `<input` — the shape the probe's first version missed.

Oracle verdicts worth knowing (all machine-checked, not reasoned):

| input | warns | why |
|---|---|---|
| `<inputx type="checkbox">` | no | `<input\b` — no boundary between `input` and `x` |
| `<input-x type="checkbox">` | yes | `-` IS a word boundary |
| `<input data-type="checkbox">` | yes | `\btype` — the `-` before `type` is a boundary |
| `<input mytype="checkbox">` | no | no boundary inside `mytype` |
| `<input type=checkbox>` | no | the quotes are required |
| `class="xtodo"` / `class="todos"` | no | `\b(?:checklist\|todo)\b` is not a substring match |
| `class="a todo b"` / `class="TODO"` | yes | word-bounded, and the rule is case-insensitive |
| `<inputé …>` / `class="todoé"` | yes | JS `\b` is ASCII-only — é IS a boundary there |
| `<input type="checKbox">` (KELVIN) | no | JS `/i` never folds a non-ASCII char onto ASCII |
| `x` + U+000B/U+000C/U+0085 + `- [ ]` | no | not JS line terminators (they ARE ICU's) |
| `-` + U+FEFF + `[ ] milk` | yes | U+FEFF is JS `\s` (and is NOT ICU `\s`) |

Wired into `ChecklistWarningTests.corpusAgreement`, which pins the row counts so a truncated
or differently-regenerated fixture cannot masquerade as a pass.
